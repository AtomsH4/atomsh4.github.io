# 关于页粒子图谱技术选型与初步验证

日期：2026-11-03。基线提交：`2eea17e`。

后续进展：用户已确认选型，独立交互原型已完成，见[原型与验证记录](2026-11-03-about-graph-prototype-validation.md)。以下依赖体积和数值实验记录保留为选型时的基线。

建议使用现有 **Astro + React**，由 **d3-force 3.0.0** 计算受约束的二维布局，**HTML 节点 + SVG 关系线**承载内容与交互，**Canvas 2D** 绘制装饰粒子。通过粒子大小、透明度和轻微视差形成纵深感。移动端采用分支聚焦，保留正常文字大小和点击区域。

本轮完成代码结构调查、候选依赖打包、真实内容拓扑检查和独立数值实验。实验未接入正式页面，也不是可交互界面原型；浏览器帧率、真实字体避让、触控手势和视觉效果还需要下一阶段验证。选型是建议，正式页面设计尚未确认。

## 现有站点与接入条件

- `src/pages/about.astro` 当前只有静态经历和联系信息，使用 `BaseLayout`。
- 已安装 Astro 7.2.9、React 19.2.8、Three.js 0.186.0、React Three Fiber 9.7.0。无需增加应用框架或后端。
- 推荐页使用 React Three Fiber；首页 Hero 使用独立 shader。两处均已有减少动态效果、暂停或降级处理可参考，但图谱不直接耦合它们的业务组件。
- 实际浏览器基线：关于页只有导航 React 岛、没有 Canvas；1408px 视口下主内容宽度为 1152px，无横向溢出。Three.js 已安装不等于关于页已经下载了它。
- Astro 支持服务端生成框架组件 HTML，再通过 `client:*` 激活交互。关于页主图位于首屏，建议使用 `client:load`；初始内容和可访问列表仍由服务端提供。[Astro 框架组件文档](https://docs.astro.build/en/guides/framework-components/)

## 三种方案比较

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| d3-force + HTML/SVG + Canvas 2D | 内容和特效分层；文字清晰；可直接使用原生按钮；不依赖 WebGL；便于适配现有主题 | 需实现坐标同步、手势、粒子绘制和真实标签避让 | **推荐**，17 个节点的规模适合定制 |
| 现有 Three.js / React Three Fiber + d3-force | 依赖已安装；空间粒子、景深和摄像机表现更自由 | 仍需承担该页的 3D 下载与初始化；文字、拾取、触控和 WebGL 降级更复杂 | 若明确需要自由旋转的三维星系，再优先考虑 |
| react-force-graph-2d 1.29.2 | 已提供拖动、缩放、平移和节点事件；快速制作通用图谱 | 需要围绕 Canvas 补充语义内容；个性化排版与移动端聚焦仍需开发；引擎开销更大 | 适合通用数据图谱，当前内容规模收益有限 |

`react-force-graph` 官方提供分别基于 Canvas 和 Three.js/WebGL 的二维、三维包；其内置交互能减少通用图谱开发工作，但不直接解决本站的内容浏览与视觉要求。[官方项目说明](https://github.com/vasturiano/react-force-graph)

R3F 支持按需渲染，但持续运动的粒子仍需要持续请求帧。能复用依赖并不意味着持续动效没有设备成本。[R3F 性能文档](https://r3f.docs.pmnd.rs/advanced/scaling-performance)

│   └── 流行

│   └── ACM

    ├── 卡牌

共 17 个节点、16 条关系。以中心为第 0 级，类别是第 1 级，子项是第 2 级。这里是以个人为中心的兴趣图谱；首版关系是树结构，后续有明确内容依据时再增加跨分支关系。

数据以稳定 `id`、`label`、`parentId`、可选说明和链接描述；层级由父链推导，不把页面写死为两层。实验通过临时的第三级测试节点验证父链可扩展，不将测试节点纳入展示内容。正式扩展第三级布局仍需单独验收。

现有项目集合、ACM 题解和 EVA 推荐可以作为后续详情或第三级内容来源。技术栈能力和其他兴趣细节不从站点依赖推断，也不编造个人经历。中心节点采用 AtomsH，不因此修改全站现有 AtomsH4 品牌和 SEO。

## 初步验证结果

实验源代码：[`about-graph/validate.mjs`](about-graph/validate.mjs)。原始结果：[`about-graph/results.json`](about-graph/results.json)。所有候选依赖均安装在临时目录，站点 `package.json` 和锁文件未变。

### 依赖和构建

| 检查 | 结果 |
| --- | --- |
| 当前站点生产构建 | `npm run build` 通过；Astro 检查 0 errors、0 warnings、36 hints；生成 44 页 |
| d3-force ESM 导入 | 在 Node 24.15.0 中成功，无需 DOM 或浏览器全局变量 |
| d3-force 全部公开导出打包 | minify 后 15,623 bytes；gzip 后 **5,865 bytes，约 5.7 KiB** |
| react-force-graph-2d 默认导出打包 | minify 后 186,122 bytes；gzip 后 **61,924 bytes，约 60.5 KiB** |

打包使用 esbuild 0.28.2、浏览器 ESM、minify；React / React DOM 作为外部依赖。数字包含对应入口可达的依赖，**不是完整页面体积，也不是功能等价实现的体积对比**：d3-force 只有物理布局，图谱交互与粒子代码尚未计入；React 图谱组件还包含渲染与交互。候选依赖的传递版本以本次临时安装结果为准，重新安装可能产生不同体积。

构建仍报告现有推荐页大 chunk 提示，以及既有 schema 弃用 hints。它们不是本轮引入的问题，也不能据此推断新图谱的最终体积。

### 拓扑与布局数值实验

| 检查 | 结果 |
| --- | --- |
| 17 个节点、16 条关系、唯一 ID、完整父链、无环 | 通过 |
| 中心节点固定 | 使用 `fx/fy` 固定 AtomsH；模拟拖动其他节点后仍保持中心坐标 |
| 静态内容不被模拟污染 | 冻结内容数据，复制出模拟节点与关系后运行；原数据保持不变 |
| 桌面 1120 × 620 舞台 | 300 次迭代后无碰撞代理相交、无边界越出 |
| 数值拖动与松开 | 临时固定一个叶节点，再解除固定并重新迭代；中心不移动，收敛结果通过几何检查 |
| 移动端 280 × 560 舞台 | 四个分支分别聚焦，显示根节点、当前类别及其子项；每种情况均无碰撞代理相交、无边界越出 |
| 17 节点初始化与 300 次迭代 | 预热 5 次后测量 30 次；本机 p50 **16.8ms**，p95 **22.7ms** |

本实验使用分支锚点、位置力、关系力、排斥力和圆形碰撞代理。圆形半径由 14px 中文 / 8px ASCII 的估算字宽加留白得到，**并非真实字体包围盒**。计时只包含 Node 中的模拟初始化和迭代，不包含 DOM、Canvas、浏览器布局和绘制，不能转换为页面 FPS。这里只验证一组初始位置和一次数值拖动，没有覆盖任意拖拽、运行时增删节点或浏览器尺寸切换。

d3-force 会修改传入节点，并自动启动内部计时器；实现时应复制内容数据并明确管理计时器。它支持停止后手动迭代，以及通过 `fx/fy` 固定节点。[D3 模拟文档](https://d3js.org/d3-force/simulation)

位置力可以将节点拉向给定目标。本实验为四个分支设置稳定锚点，避免纯自由力布局使类别方向持续变化。[D3 位置力文档](https://d3js.org/d3-force/position)

### 移动端结论

桌面布局的水平碰撞代理总跨度约为 765px。若全图直接适配 320px 视口下的 280px 内容区，整体缩放约为 0.366，44px 点击目标只剩 **16.1px**；390px 视口的 350px 内容区也只有约 **20.1px**。这是缩放计算结果，不是手机实测。

因此建议桌面支持全图，手机默认显示中心与四类入口，选择类别后显示中心 → 类别 → 子项，并提供返回总览和四类切换按钮。子项的文字与点击尺寸保持正常大小，三级内容继续沿当前路径展开。移动端布局需要重新编排，不能只缩放桌面画布。

## 建议的实现边界

这部分用于确定后续原型范围，尚未接入页面：

- **内容数据**只描述节点和关系，提供图谱与静态列表的共同来源。
- **交互状态**由一个 React 岛管理展开集合、选中节点、当前路径和移动端分支；点击类别展开，点击子项显示说明或链接。键盘提供同等操作。
- **布局模块**复制可见节点后运行 d3-force；固定中心，以稳定分支锚点和标签边界约束布局。每帧坐标保存在 ref，直接同步节点与连线，不为每一帧更新整棵 React 树。
- **HTML/SVG 层**使用原生按钮、清晰标签与焦点样式，显示连接和路径高亮。桌面允许节点拖动并回归；移动端先保障点击和页面纵向滚动。
- **Canvas 2D 层**只绘制装饰微粒、光晕和沿关系流动的粒子；`aria-hidden`、不拦截指针。它与节点使用同一坐标系；装饰粒子不参加图谱碰撞计算。
- **生命周期**统一调度模拟和装饰动画；页面隐藏或舞台离屏时暂停；减少动态效果时显示静态布局并停用持续粒子。Canvas 初始化失败仍能使用 HTML/SVG 图谱，JavaScript 失败仍可阅读服务端内容与联系链接。

首轮沿用现有浅色 / 深色主题和蓝紫色系，用层次、亮度与轻微视差表现粒子空间。尚未选择暗色星空等全新视觉方向。粒子数量、DPR、光晕强度与最终舞台高度需通过真实原型确定。

## 下一阶段的原型验收

1. 在独立、非导航入口的本地验证页接入全部 17 个真实节点，验证展开、收起、路径高亮、拖动和重置；正式关于页替换在原型结论之后进行。
2. 使用真实中文字体测量标签包围盒，验证 1280px 桌面、390px 与 320px 手机；测试全图、四个分支和返回总览，保持可读字号与至少 44px 的产品点击目标。
3. 实测 Canvas 绘制、图谱动画与拖动耗时。初始目标为桌面接近 60fps、手机稳定 30fps 以上；这是验收目标，当前没有实测结果。粒子初始预算可从桌面 96、手机 32 起，按实际设备表现调整。
4. 检查键盘、主题切换、减少动态效果、离屏与后台暂停、Canvas 失败、无 JavaScript，以及进入离开页面后的资源释放。
5. 原型通过后再锁定正式依赖、确定新页面布局，并将经历和联系信息整合进图谱内容与可访问文本。无需新增数据库、图数据库、React Flow 编辑器或运行时外部 API。

## 复现实验

在仓库根目录执行。候选包只写入临时目录，使用仓库已有 esbuild：

```sh
validation_dir=$(mktemp -d /tmp/atomsh-about-graph.XXXXXX)
npm install --prefix "$validation_dir" --no-package-lock --no-audit --no-fund --ignore-scripts d3-force@3.0.0 react-force-graph-2d@1.29.2
cp docs/research/about-graph/validate.mjs "$validation_dir/validate.mjs"
./node_modules/.bin/esbuild "$validation_dir/node_modules/d3-force/src/index.js" --bundle --format=esm --platform=browser --minify --outfile="$validation_dir/d3-force.bundle.js"
./node_modules/.bin/esbuild "$validation_dir/node_modules/react-force-graph-2d/dist/react-force-graph-2d.mjs" --bundle --format=esm --platform=browser --minify --external:react --external:react-dom --outfile="$validation_dir/react-force-graph-2d.bundle.js"
node "$validation_dir/validate.mjs"
```

脚本会检查拓扑、中心固定、数据隔离、模拟拖动、桌面与四种手机分支布局，并在临时目录输出 `results.json`。数值计时会随设备与负载变化，不以固定毫秒值判定通过。
